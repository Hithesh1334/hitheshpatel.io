The short version

Most of my work starts the same way: a data system that's brittle, tangled, or quietly wrong. The rebuild is my job.

For 2+ years at phData, I've modernized financial data ecosystems for enterprise clients: secure, production-grade pipelines on dbt, Snowflake, and Airflow.

Lately I've been wiring LLM agents and custom MCP tooling into our engineering workflows: collapsing multi-day investigations into a single prompt, without handing anyone the keys to a black box.

I care about three things: code the next person can read, flagging problems early, and owning what I ship after it goes live.

working prototype
Prism: Building Data Pipelines End to End with AI
React 19TypeScriptViteTailwindFastAPIPythonLangChainLangGraphMCPClaude CodeGitWebSocketsSQLite
  • A tool where the canvas is the pipeline — ingestion → transformation → dashboard, each node a real stage of data engineering. Transformation is built end to end; the other two are scaffolded.
  • Every stage opens a chat session, and you build it by describing it: an ingestion connector, the models that turn warehouse data into something report-ready, then the visualization on top.
  • Runtime MCP server management is how the agent reaches the warehouse and APIs — add stdio, SSE, HTTP or WebSocket servers from the UI, no restart. One that fails to connect says why instead of quietly showing zero tools.
  • Made tool approval a real gate, not a UI formality — the agent pauses before every call and waits for an explicit Allow/Deny, with a dedicated socket reader so decisions can arrive mid-turn.
  • Skills: reusable instruction blocks injected into the system prompt, suggested by keyword match as you type.
  • React 19 + FastAPI over a persistent WebSocket, streaming tokens with a mid-generation stop. The LLM provider swaps between Gemini and Anthropic behind one env var, and frontend and backend deploy independently.
✓ ingestion → transformation → dashboard ✓ every tool call gated ✓ MCP servers added at runtime
